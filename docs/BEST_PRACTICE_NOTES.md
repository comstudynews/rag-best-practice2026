# Best Practice 해설

## 1. 왜 Baseline부터 확인하는가

개선 기법을 먼저 정하고 넣는 것이 목적이 아닙니다.

올바른 순서:

```text
Baseline 실행
→ 검색 결과와 답변 확인
→ 실패 유형 분류
→ 문제에 적합한 개선 전략 선택
→ 동일 조건 재평가
```

## 2. 이 예제에서 Hybrid Search를 구현한 이유

기술지원 문서에는 자연어 설명과 함께 다음과 같은 정확한 토큰이 등장합니다.

- ERR-NET-403
- ERR-AUTH-017
- DEMO-RAG-ENT
- TCP 443
- /var/lib/demo-rag-2026/backup/

Dense Retrieval은 의미 검색에 강하고 BM25는 정확 문자열 검색에 강점이 있습니다.

따라서 이 샘플은 **정확 키워드 유형의 문제를 검증하기 위한 비교 전략**으로 Hybrid Search를 구현합니다.

중요한 점은 실행 전에 "Hybrid가 더 좋다"고 결론내리지 않는 것입니다.

Baseline에서 키워드 유형이 이미 잘 검색된다면 다음과 같이 기록합니다.

> 키워드 유형에서 명확한 Baseline 약점이 확인되지 않았다. Hybrid Search는 비교 실험으로 실행했으며, 결과가 동일하거나 악화된 경우 그 Trade-off를 기록한다.

## 3. 좋은 결과 문서의 특징

- Baseline과 Improved를 같은 질문으로 비교
- 검색 결과와 답변을 분리해 분석
- 평균 지표와 질문별 결과를 모두 제시
- 개선된 결과만 선택적으로 제시하지 않음
- 개선되지 않은 이유를 설명
- 자동 지표의 한계를 구분
- 사람이 확인해야 하는 Generation 품질을 별도로 기록

## 4. 평가셋 확장

AI는 질문 후보 생성에 사용할 수 있습니다.

그러나 AI가 만든 질문을 자동으로 Gold Set으로 승격하지 않습니다.

```text
Seed → AI Candidate → Human Review → Gold Set
```

## 5. 모범답안의 의미

Best Practice는 특정 코드 구조를 그대로 복제하는 정답이 아닙니다.

주제와 문서가 달라지면 다음도 달라질 수 있습니다.

- 평가 질문
- Baseline 실패 유형
- 선택할 개선 전략
- 효과가 나타나는 지표
- 남는 한계

따라서 핵심은 **코드 형태가 아니라 판단 과정과 근거**입니다.
