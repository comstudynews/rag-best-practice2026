# Best Practice 해설

## 1. 이 예제에서 Hybrid Search를 선택한 이유

기술지원 문서에는 자연어 설명뿐 아니라 다음과 같은 정확한 토큰이 자주 포함됩니다.

- ERR-NET-403
- ERR-AUTH-017
- AsterDesk-ENT
- TCP 443
- /var/lib/asterdesk/backup

Dense Retrieval은 의미 기반 질문에 강하지만, 코드·경로·포트·제품명처럼 정확한 문자열이 중요한 경우 Sparse Retrieval이 유리할 수 있습니다.

따라서 이 예제에서는 Dense + BM25를 결합합니다.

## 2. 좋은 종합실습의 특징

좋은 제출물은 코드가 길지 않아도 다음이 명확합니다.

- 왜 이 문제를 선택했는가?
- Baseline에서 무엇이 실패했는가?
- 어떤 개선을 왜 선택했는가?
- 동일 질문으로 다시 평가했는가?
- 실제로 무엇이 좋아졌고 무엇은 그대로인가?
- 한계를 숨기지 않고 설명하는가?

## 3. 좋지 않은 제출물의 예

- Baseline 측정 없이 바로 Advanced RAG를 구현
- 여러 기법을 넣었지만 선택 이유가 없음
- 개선 전과 후의 질문이 다름
- 최종 답변만 보고 Retrieval 문제를 분석하지 않음
- 평가 질문이 전부 비슷한 유형
- AI가 만든 질문을 검수 없이 Gold Set으로 사용
- 개선되지 않은 결과를 삭제하고 좋은 사례만 제시
